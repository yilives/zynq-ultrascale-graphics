# MC 模型质量第五轮与性能取舍（2026-10-23）

已训练并上板验证新的动漫学生模型，增加可选入口 `rix-classicube-style-v5`。在模型固定后采集的一条新平地路线、8 张采样图上，最终融合画面对教师融合参考的平均 RGB 误差从 **4.0520 降至 2.3271，降低约 42.57%**。该指标衡量教师模仿误差，不是人工审美评分，也不能代表所有地图。

新模型实际运行 62 秒，完成显示 1593 帧，约 **25.68 FPS**。完整显示像素、实际 FPGA 张量和 LCD 回读均通过独立整数金值检查。新模型只作为可选版本，现有默认模型及油画模型保留。

## 使用与对照

开发板 Linux：

```sh
# 新动漫候选，键鼠操作；未开启自动游玩
rix-classicube-style-v5 --style anime --seconds 1800

# 原默认动漫模型对照
rix-classicube-style --style anime --seconds 1800

# 原油画模型；本轮油画新候选没有采用
rix-classicube-style --style oil --seconds 1800

# 仅用于自动验证
rix-classicube-style-v5 --seconds 30 --autoplay
```

原有强度、保护区域和键鼠配置沿用现有会话入口。`v5` 入口固定动漫模型及已验证的运行时，不接受覆盖 `--model-file` / `--executable`。新模型主要改进配色和局部风格响应；这仍是小型学生网络，没有达到完整 AnimeGAN/CycleGAN 的全局画风能力。

同一板测帧的三列对照：源图、旧模型整数参考、新模型已核验的 FPGA 输出。旧模型一列是相同输入的离线整数参考，不冒充另一次板上同步拍摄：

## 训练修复

发现原身份初始化使两个隐藏层的输出通道 6、7 的权重与偏置均为零，ReLU 后始终为零；连接到这些零特征的权重无法获得有效梯度。对原导出 INT8 模型做实际中间张量统计，也确认只有 **6/8 个隐藏通道有活动**。

新训练保留原已学特征，对这两个通道使用小幅随机权重及正偏置，使其能参与学习；初始末层新增连接仍为零，避免一开始任意改变颜色。最终 INT8 中间张量在五张真实图上确认两个隐藏层均为 **8/8 通道有活动**。相同数据、步数和损失的控制组保留原零通道，复活通道组仅按验证集目标选取。

网络物理形状仍为 **3→8→8→3，三层 3×3，7×7 感受野**。导出仍为 RIXCNN1、7116 B，每帧核心 414738 周期，100 MHz 下约 4.147 ms。没有因这次权重更新增加层、通道数或重新综合 FPGA。原本物理上已有这些计算通道；新训练使其获得有效权重。

训练还采用了全程量化感知、带三像素上下文的裁剪损失、原运行时一致的保护区域，以及教师像素/梯度、原图边缘、低频色彩损失。首轮两个风格各做控制组和复活组各 5000 步，均按验证集选检查点。

## 数据、运动约束与留出规则

初始数据集共 36 张：17 张训练、9 张同世界视角验证、10 张初始留出/开发评估。新增 26 张由真实游戏的 SNP1 租约快照取得，复制后再次确认租约所有权，保存源帧号、单调时间戳和 SHA；没有读取游戏仍在修改的实时 PS 槽。采样间隔约 500 ms，不能称作连续显示帧。

首轮发现新模型风格响应更强，同时移动视角的残差变化增大，随后加入估计光流约束。使用训练序列的 11 对图和验证序列的 5 对图；严格剔除跨训练/验证边界的配对。前后向光流一致性、源图匹配误差和世界区域共同筛选有效像素。第二轮动漫模型再训练 3500 步，以验证图像目标加运动项选取第 2000 步。

## 性能尝试与取舍

尝试了常驻取帧线程、常驻四路快照读取线程及二者组合。主机生命周期、异常传播、停止/析构顺序和普通内存快照数值检查通过；这些检查不等同于 Device 读取吞吐验证。

12 秒实际游戏筛选中，原版两端约 27.56/27.37 FPS，取帧池约 26.96、读取池约 26.16、组合约 26.03 FPS。随后对较好的取帧池做 25 秒 ABBA：

|配置|加权最终风格 FPS|神经进程总 CPU ms/完成帧|
|---|---:|---:|
|原版|25.7678|83.4856|
|取帧池|25.5929|83.8570|

CPU 用时是所有神经进程线程的合计，不是单帧墙钟延迟。线程池没有实际收益，**没有合入正式入口**。当前主要开销仍是不可缓存的快照回读、融合和显示写回，减少线程创建不能解决这些传输成本。

同一正式运行时、仅换模型的 20 秒 ABBA：原模型 **26.4322 FPS**，新模型 **25.9343 FPS**，约 -1.88%。本轮没有获得新的帧率提升，也不据此宣称新模型完全无性能成本；核心周期和所有数据尺寸相同，单组对照仍有调度/场景变化。新模型单独 62 秒长测为 1593/62.038=25.6778 FPS。

## 工程验收与安装

**19/19 项工程验收通过**，汇总器读取真实报告、产物和 SHA，见 `report/classicube-style/quality-v5/acceptance.json`。

- 新模型量化感知结果与导出整数参考在 36 张图的 RGB 输出上零差异；原两种首轮候选预览另有 23040000 个 RGB 值的实际 C++ 缩图/融合对照零差异。
- 最终新动漫模型实际 FPGA 输出与独立整数模型相同，同帧源图到输入匹配；完整 384000 显示像素、6000 点 LCD 回读、保护区域均零差异。
- 已安装可选命令通过真实 XTEST→X11→SDL 的 12 项键鼠检查，包括移动、跳跃、松开、视角、栏位、滚轮、菜单和恢复游戏；随后重复启动并自然结束。实体 USB 键鼠仍未在本轮验证。
- 可选安装器有 38 项 Linux 真实临时文件/失败注入检查。固定 SHA 校验，保留未知文件，不改原默认入口；安装前后维持 root 32 MiB、SD 16 MiB 空间阈值。
- 一次 QA 直接导入调度 helper 生成了 `__pycache__`，被公共缓存完整性检查正确拒绝。已持锁核对 12 个载荷未变，将整个缓存保存在 RAM 证据目录，然后由正式入口从 SD 重建干净缓存；没有删除未知文件或放宽校验。测试脚本改为禁用字节码，重复启动及最终缓存检查通过。首轮失败记录保留。
- 原 31 个通用神经文件、9 个 MC 包内文件、私有 GL、普通 MC 入口、BOOT/DT、四组启动备份及既有风格回退文件均核对保留。
- 最终 GPU 各队列计数均为 21127，status=3，错误计数为零，无 GPU 客户端或租约；root 可用 34402304 B、SD 可用 16834560 B。

工程一致性通过不代表艺术质量验收：仍记录 `quality_acceptance=false`、`temporal_acceptance=false`。目前数据只覆盖少量地图与视角、同一生成种子，平地路线也不是八个独立世界。后续需要更多种子、光照/水面/建筑/菜单及运动路线，再判断是否替换默认模型。

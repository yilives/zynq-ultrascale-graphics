# NNS2：CNN 流水线与 FPGA 五倍放大

本文保留上一阶段 23.79 FPS 的发布证据；当前已部署的 28.44 FPS 和新启动包见 [帧复制突发优化记录](NEURAL_STYLE_COPY_BURST_2026-10-20.md)。本文的整机资源、包哈希和 41/21 检查数属于上一阶段，完整原始报告另在 `report/neural-style/present-v1/`。

## 数据顺序

```text
ARM 游戏逻辑
  → RasterIX：400×240 RGB565 游戏画面
  → SNP1 独立快照 → A53 四核取帧、缩小到 160×96
  → PIO → FPGA 三层 INT8 风格网络 → PIO
  → A53 打包 160×96 XRGB，写入 PL 双缓冲
  → FPGA 中心对齐双线性五倍放大 → 800×480 RGB LCD
```

此前也是低分辨率风格化之后放大；本轮将放大从 A53 移入 FPGA。放大器没有运行新的神经超分模型，也不是 FSR；两套风格网络权重保持原样，画质仍受小网络、160×96 输入和 7×7 感受野限制。

## 核心改动

旧核每个卷积核位置依次执行 READ、MULT、REDUCE、ACCUM。新核将这些阶段流水化，每拍发出一个核位置的计算。两个交替累加槽允许前一个像素收尾时发出下一个像素的计算；每层最后仍等待量化结果完整写入 BRAM，再切换读写特征银行。

| 项目 | NNS1 | NNS2 |
|---|---:|---:|
| 160×96 核心计算周期 | 1,843,200 | 414,738 |
| 名义 100 MHz 核心时间 | 18.432 ms | 4.14738 ms |
| 计算周期公式 | 120×像素数 | 27×像素数+18 |
| 独立核 DSP | 65 | 65 |
| 独立核 LUT / FF | 3,712 / 1,230 | 4,105 / 1,813 |
| 独立核 BRAM tile | 55 | 55 |
| 独立核 WNS / WHS | +1.827 / +0.039 ns | +2.450 / +0.042 ns |
| 每帧显示缓冲写入 | 1,536,000 B | 61,440 B |

核心计算缩短约 77.5%，约为原来的 4.44 倍速度。上述核心时间不含取帧、PIO、换页；整条链路帧率须使用实板报告中的独立测量。

INT32 累加、负数舍入、ReLU、饱和、边界复制和权重 ABI 保持一致。`bank0` 的输入装载和卷积写回共用显式地址 / 数据选择器，保证可推断为 BRAM 的单写端口。

## 放大和寄存器

新增后处理 mode 3，读取 160×96 XRGB 双缓冲，输出 800×480；原 mode 0 / 1 / 2 保留。输入坐标为 `max(0,x-2)/5`、`max(0,y-2)/5`，每轴五相，边缘复制，RGB 加权和加 12 后除 25。已有四行带标签缓存承担行复用。

### DDR 突发缓存

首轮 NNS2 已在实板验证 CNN 周期和图像正确，但无诊断连续显示只有 10.878 FPS。五倍放大的输入消费较慢，直接把像素端的背压传到 MIG，会让一个 256-beat 突发长时间停在 DDR 返回通道，影响其他读取者。该问题不能只从 CNN 计算周期判断。

修正版只为神经模式加入 256×128-bit 突发缓存，占额外 2 个 BRAM tile：先完整接收一次 DDR 突发，再从本地缓存向放大器供数。慢速消费期间没有悬挂的 DDR 事务。LR / 原生路径保留直接传输，避免降低原生像素吞吐。

缓存使用一个显式读地址选择器和同步读端口。独立读取器综合为 385 LUT、98 FF、2 BRAM tile；构建还会检查整机网表中实际存在对应 RAMB 原语。早期分支式读取写法曾展开成 33,059 个 FF，该原型没有部署，保留在 `register-buffer-prototype/`，不能只凭 `ram_style` 属性认定已使用 BRAM。

新的连续两帧仿真同时检查全部 768,000 个输出像素和每个 DDR 返回握手；神经模式不允许对有效 DDR 返回施加背压。将同一断言用于归档旧读取器会复现失败，见 `neural-unbuffered-negative.log`。还测试了缓存等待期间中止、在途突发中止并排空、旧模式回归和原生短突发负对照。

CNN 地址仍是 `0xA0030000`：

| 偏移 | NNS2 含义 |
|---|---|
| 0x00 | `0x4e4e5332`，NNS2 |
| 0x04 | 高 16 位高度 96，低 16 位宽度 160 |
| 0x28 | 实测核心计算周期 |
| 0x38 | 配置应有的核心周期，414,738 |
| 0x3c | 能力 3：bit 0 流水线，bit 1 配套整机五倍放大 |

新设备树为 `rasterix,cnn-int8-v2`，另有 `rasterix,neural-scale5x=<1>`。新版程序同时支持 NNS1 和 NNS2：先检查设备树，再读 magic，只有 NNS2 才访问新寄存器；同时具备设备树标记和硬件放大能力才选择 mode 3。NNS1 使用原 A53 放大路径。历史基准二进制只支持 NNS1；NNS2 基准工具自动避开这些旧程序。

## 验证和性能记录

`report/neural-style/rtl-verification.json` 绑定源文件及测试日志 SHA256。CNN 小尺寸、完整 160×96、两套实际权重和 AXI 协议测试通过；完整五倍放大检查 384,000 个像素，AXI 读取 / 串行器 / 放大连续两帧检查 768,000 个像素，含随机数据间断与请求延迟。

实板前后对照使用同一新版执行文件、同一权重、Neverball 自动操作和相同取证流程；两次独立游戏运行不保证画面逐帧相同。取证模式额外在 CPU 生成完整放大参考并落盘，该参考不参与 mode 3 显示；`diagnostic_seconds` 单列这部分成本。正式入口连续测试不启用这些诊断操作。

修正版已更新实际 SD 并正常重启进入 Linux。工程检查 **41/41**、硬件优化检查 **21/21** 全部通过，结果在 `hardware-optimization.json`、`acceptance.json`、`pl_live/host-verification.json`、`board-state.json` 和 `neural_style_*` 报告。首版证据保留在 `hardware-v1/`，首次 NNS2 的回退性能证据保留在 `initial-nns2/`。

| 实板指标 | NNS1 基线 | NNS2 直接读取 | NNS2 突发缓存修正版 |
|---|---:|---:|---:|
| 油画固定张量，含 PIO 推理 | 32.8933 ms | 18.6193 ms | 18.6139 ms |
| 动漫固定张量，含 PIO 推理 | 32.8976 ms | 18.6228 ms | 18.6214 ms |
| 油画游戏，含诊断 | 12.2422 FPS | 10.5624 FPS | 17.5475 FPS |
| 动漫游戏，含诊断 | 11.9724 FPS | 11.8923 FPS | 18.4732 FPS |
| 动漫正式入口，无诊断 | 12.0558 FPS | 10.8780 FPS | **23.7876 FPS** |

最终正式入口连续运行 62.0492 秒、处理 1,476 帧，较上一版无诊断结果约快 1.97 倍。CPU / FPGA 两种后端的时限退出和 SIGTERM 退出均通过；卸载空闲驱动后，正式入口自行重新加载并完成本轮连续测试。所有 GPU 错误计数为 0，结束后无残留游戏、后处理进程、快照租约或过期事件。

相对首次 NNS2，连续测试的每帧快照等待从约 45.84 ms 降到 8.59 ms，四核读取从约 14.85 ms 降到 2.51 ms；含 PIO 推理约 18.63 ms，换页等待约 10.66 ms，仍是后续提速需要处理的成本。新模式的 `scale_seconds` 只统计 ARM 的低分辨率打包；不能将它解释成整张 800×480 的 FPGA 放大时间。

两组真实游戏输入均由主机 NumPy 独立复算，每组 122,880 个张量值逐位一致；各 61,440 字节原生显示缓冲与 6,000 个真实 LCD 采样也全部一致。[本轮 LCD 采样预览](../report/neural-style/pl_live/actual-lcd-comparison.png)来自两个不同游戏时刻，不能用于同帧画质对比。网络和权重没有变更，`quality_acceptance` 仍为 `false`。

整机布线报告使用 46,877 / 70,560 LUT（66.44%）、48,497 / 141,120 FF（34.37%）、137 / 216 BRAM tile（63.43%）及 152 / 360 DSP（42.22%）。最终时序为 WNS +0.867 ns、WHS +0.011 ns，建立与保持违例总和均为 0。相对初轮 NNS2，突发缓存修复增加 90 LUT、106 FF 和 2 BRAM tile。

## 启动与回退

```sh
rix-neural-games neverball --style anime --backend pl-int8 --seconds 60 --autoplay
# 油画：--style oil；ARM 对照：--backend cpu-int8
```

启动分区旧 NNS1 文件保存在 `rasterix-neural-fast-backup-20261020/`，初轮 NNS2 在后续更新时保存在 `rasterix-neural-buffer-backup-20261020/`，更早的初版前文件仍保存在 `rasterix-neural-backup-20261020/`。升级工具先验证包、当前文件和备份的 SHA256，先更新 BOOT.BIN，再更新 system.dtb，逐个同步并回读校验。原 U-Boot 控制设备树、PS 初始化一致性、XSA 和 BOOT 中实际 PL 负载均有打包检查。

本轮 BOOT.BIN 为 6,560,724 字节，SHA256 `e9586c009ebc6b26feca37876acd85b72dea0f9039e925a4c2ff8d7afcd6a015`；设备树为 31,292 字节，SHA256 `f4a2d7c54efde6b05bff6974a41075687a2f546a8c84f99ff883fd1201cb42dc`。运行包 SHA256 为 `cf3949277a6ebb8d1be1d6c51022959743ad580e07be6ca908b85a965427926a`。正常重启后的启动标识为 `e7c7b890-c12e-4ead-809b-406cafdce842`；本轮没有进行断电冷启动测试。

后续复制桥升级时，fast-backup 和 buffer-backup 的 BOOT 已经校验后压缩为 `BOOT.BIN.gz`，设备树保留原文件。需要回退这些版本时，先正常退出游戏和后处理，用 `gzip -dc BOOT.BIN.gz` 还原原 BOOT.BIN，并配对恢复 system.dtb、同步后正常重启；不能直接把 gzip 文件改名。新版用户程序兼容 NNS1。最近一次 NNS2 回退对保存在 `rasterix-neural-copy-backup-20261020/`，仍为普通文件。历史运行包缓存另经逐个 SHA 校验移入 SD 的 `rasterix-neural-cache-archive-20261020/`，保留副本并释放根分区空间。本轮只更新配套文件，不生成整卡 `.img`。

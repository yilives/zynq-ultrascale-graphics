## 速度优化的依据

原 NIP1 单帧约 12.9 ms，其中卷积约 4.63 ms，PIO 输出约 6.85 ms。卷积执行时间已不是这段推理链路最大的部分。

先做了串行/重叠/重叠/串行 ABBA 对照，每轮 150 帧。串行分别为 24.8884、24.8805 帧/秒，重叠分别为 24.7419、24.7798 帧/秒，均值约下降 0.50%，因此没有采用该开关作为加速结果。四轮末帧与 LCD 采样均通过独立复核，见 [ABBA 记录](../report/neural-style/quality-v7-speed/acceptance.json)。

新 NGR1 输出接口增加八像素快照窗口，读操作无副作用，CPU 批量读完后用序号明确确认消费。像素值、卷积核心、层数和时钟保持同一计算契约；目标是减少 CPU 与控制总线逐像素往返的开销。

| 寄存器 | 含义 |
|---|---|
| 0x0000 | NGR1 标识 0x4e475231 |
| 0x0044 | 适配器 ABI 0x00040001 |
| 0x0048 | 分组就绪、故障、末组和有效像素数 |
| 0x004c 读 / 写 | 当前分组序号 / 空闲时设置分组模式 |
| 0x0050 读 / 写 | 当前分组模式 / 写入预期序号确认消费 |
| 0x0100…0x011c | 八个可重复、乱序读取的像素快照字 |

接口已通过 1×1、7×5、160×96 的 14 帧回归，包含原 PIO 协议、尾组、重复读、随机读序、背压、错误和重复确认。ARM 程序已通过 16 项身份契约检查、8 组原像素黄金向量，并完成 AArch64 构建。全板构建及独立配置再生审计已通过：65058 LUT、71711 FF、189.5 BRAM、325 DSP；WNS +0.159 ns、WHS +0.010 ns。相比 NIP1 增加 328 LUT、266 FF，BRAM 与 DSP 不增加。三份原始配置字节一致，SHA256 为 `c7e5f78f059a68e679b8f2fed7a1284d81ea5f3fdd8fd93c2351b51f0fe8e4d2`。[整机验收](../report/neural-style/group-r1/board/acceptance.json)。Vivado 工程为 `build/vcgr1/rix_cgr1.xpr`。同一 NGR1 位流上的固定输入 ABBA 已通过：

| 单帧阶段中位值 | 原子读取 | 分组读取 |
|---|---:|---:|
| 输入写入 | 1.383 ms | 1.383 ms |
| 卷积等待 | 4.628 ms | 4.628 ms |
| 输出与退休 | 6.848 ms | 3.298 ms |
| 单次推理合计 | 12.876 ms | 9.321 ms |

单次推理耗时减少 **27.61%**；输出阶段耗时减少约 **51.84%**。此收益来自传输接口，CNN 卷积运算及权重保持一致。采用分组输出作为 NGR1 实验配置的默认读取方式。

48 帧固定输出、5 组实际显示末帧通过 PC 独立整数复核，共检查 5,898,240 个固定帧 INT8 值、307,200 字节原生 PL DDR 显示源回读及 30,000 个 LCD RGB565 样点。另核对 1,920,000 个软件五倍显示参考像素；物理 LCD 的本轮覆盖范围为上述采样点。[独立板上验收](../report/neural-style/group-r1/bringup-r1/acceptance.json)。

真实 Neverball 场景：原子两轮 24.8986 / 24.8316，分组两轮 24.7705 / 24.8701 帧/秒；油画分组加低 CPU 等待为 24.7492。关闭 CNN、FSR 的源帧短测为 74 帧 / 3.008 秒，约 **24.60 帧/秒**。这说明本次场景的最终帧率主要受上游源帧生成限制；推理延迟的下降没有转化为游戏 FPS 的明显提升。

测试结束后原 FPGA、原生菜单恢复；NGR1 位流及演示入口作为独立实验配置保存。

## ARM 等待策略：减少忙轮询

在同一 NIP1、同一较强漫画模型上做 spin/sleep/sleep/spin 四轮各约 6 秒对照，四轮共 599 帧。sleep 策略在约 4.63 ms 的已知核心计算预算中让出大部分 CPU，随后仍检查真实就绪、故障与截止时间。

| 归一到每帧的指标 | 忙轮询 | 让出 CPU |
|---|---:|---:|
| 核心状态读取次数 | 约 8819 | 约 356 |
| CNN 进程 CPU 时间 | 约 19.298 ms | 约 14.967 ms |
| 短测 CNN 呈现吞吐 | 约 24.80 帧/秒 | 约 24.84 帧/秒 |

状态读取减少 **95.96%**，进程每帧 CPU 时间减少 **22.44%**。进程 CPU 时间包括准备、快照线程和诊断，不等同于整个 ARM 的占用率；这组短测没有证明游戏 FPS 提升。四轮末帧均通过独立整数、原生 PL DDR 回读和 LCD 采样复核。[完整记录](../report/neural-style/runtime-yield-v7/acceptance.json)。

## 已选择的可运行包

推荐低 CPU 包位于 `build/neural-style/selected-strong-v7-lowcpu/rix-cnn-selected-strong-v7-lowcpu.tar.gz`，初版包继续保留；低 CPU 包显式使用 `--core-wait sleep`，包含两套权重、兼容运行时、校验表和启动脚本。板上 RAM 路径为 `/tmp/rix-cnn-selected-strong-v7-lowcpu`，两套权重已通过 ARM 原生 CPU 程序与实际 PL 输出的交叉核对。它不会自动重编程 FPGA。

在已有 RasterIX 游戏源帧、后处理锁可用的情况下，可分别执行：

```sh
/tmp/rix-cnn-selected-strong-v7-lowcpu/run-style.sh comic --seconds 10
/tmp/rix-cnn-selected-strong-v7-lowcpu/run-style.sh oil --seconds 10
```

该包保存用户选中的效果，原生菜单继续独立显示。通用 GUI 的风格选择入口、运动画质的人工检查和 CNN+FSR 串联不包含在以上验收结论中。

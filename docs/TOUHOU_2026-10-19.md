# AXU3EG 东方红魔乡原生移植记录

此文保留首版接入与验收。当前部署版本的原图分页、平衡画质、触摸、真实 FPS、风格化入口与最新性能数据见 [第二轮优化记录](TOUHOU_OPTIMIZATION_2026-10-19.md)；首版验收已存入 `report/touhou/baseline-v1`。

本次采用 **TH06 开源便携引擎 + ZUN 官方《东方红魔乡》0.13 体验版数据**。已在 AXU3EG 第一关自动游玩并完成 GPU/LCD 验收；优化后持续渲染 29.94 FPS、逻辑 59.98 Hz，13 项验收全部通过。它运行原作的 ANM 动画、ECL 敌机/弹幕脚本、关卡和游戏逻辑，与独立的 `rix-danmaku` 性能样例分开验收。当前交付范围是体验版，完整商业版六关未接入。

`scripts/fetch_th06_sources.ps1` 校验现有提交与文件摘要，缺失时下载。官方压缩包只提取素材，不运行 Windows EXE。五个 PBG3 包的版本入口均为 `ver0013.dat`；ST.DAT 包含 stage1、stage2、stage3。字体保留原始内容，以引擎要求的文件名交给 FreeType 读取。

构建使用已有 PetaLinux 2020.1 AArch64 SDK、SDL2/SDL2_ttf 和匹配本板配置的 RasterIX 静态库：

```powershell
.\scripts\fetch_th06_sources.ps1
wsl -d Ubuntu -- bash /mnt/f/1FPGA/Xilinxprj/prj2/rasterix-linux/scripts/build_touhou_dependencies.sh
wsl -d Ubuntu -- bash /mnt/f/1FPGA/Xilinxprj/prj2/rasterix-linux/scripts/build_th06.sh
wsl -d Ubuntu -- python3 /mnt/f/1FPGA/Xilinxprj/prj2/rasterix-linux/scripts/package_th06.py
```

上游源码保留在 `external/game-ports/th06-portable`；适配在 `/var/tmp/rix-touhou/source` 生成，对应补丁为 `patches/th06-rasterix.patch`。本地后端在 `ports/th06`。运行包和素材包输出到 `build/game-ports/packages/th06-{runtime,demo}.tar.gz`，使用固定归档时间戳；许可证与字体许可随包保留。构建不修改 BOOT.BIN、DTB 或 bitstream。

## 渲染与性能改动

链路为：ARM 原作逻辑/动画脚本 → ARM 顶点处理与批量命令 → DMA → FPGA RasterIX 三角形光栅化、纹理采样、透明/加法混合、深度 → FPGA 显示桥 → RGB LCD。

SDL/X11 提供输入事件和窗口；SDL_ttf/SDL_image 解码字体和素材。游戏像素由 FPGA 光栅化，未通过 SDL 软件渲染器绘制帧缓冲。CPU 仍承担顶点变换和纹理准备，因此不能描述为整条渲染管线都在 PL。

- 复用原引擎精灵批次；直接静态链接 RasterIX 核心，不使用会在主函数前自动创建 DMA 上下文的 GLX 库。关闭 SDL 的隐式窗口帧缓冲加速，避免再次加载 GLX。
- 保留一次待呈现约束和实际呈现 ACK；以 300 微秒状态轮询等待，避免内核毫秒级等待量化。
- 用持续存在的白纹理代替纹理名 0，修复每帧重新分配而最终耗尽 1024 个纹理槽的问题。
- 当前核心 `glGetIntegerv(GL_VIEWPORT)` 仅转换首分量。后端改用浮点查询读取全部四分量，修复二维玩家/HUD 的逆视口投影，并在启动时校验 `0,0,400,240`。
- 逻辑按单调时钟以 1/60 秒步长推进，呈现等待的时间计入下一次逻辑累计。消除原循环在阻塞呈现之后再等一次定时器造成的 20/30 FPS 波动。最多追赶 6 次更新，素材加载等长停顿有独立 clamp 日志。
- `TH06_LEGACY_PACING=1` 保留旧循环供对照。性能验收应使用视口修复后的同一二进制；早期缺失二维图层的日志不能作为最终画面性能基线。
- 资源暂按 2 的幂次缩小到硬件最大 128×128，保留归一化 UV；无需重新综合 FPGA。此策略会损失大图集、文字和细小弹幕的细节，尚未实现高保真图集分页。

内部输出 400×240，原作 4:3 内容为居中的 320×240。LCD 最近邻放大后内容为 640×480，两侧各留 80 像素，保持原作比例。当前游戏入口默认原色；不运行 CPU FSR/Arm ASR。声音暂使用 dummy 音频驱动。

官方体验版的第三关结束转入成绩页，避免访问不存在的第四关和完整版结局。第一关已实机验证，第二、第三关通关流程尚未验收。

## 板上使用

文件安装在 SD 根分区的 `/opt/rasterix/touhou`，保留既有游戏入口及启动选择。首次实验安装留下的三份 GLX 文件移入 `legacy-glx-unloaded`，避免再次被动态加载；其他游戏的私有库不变。

```sh
# 正常键盘/手柄输入
/opt/rasterix/touhou/th06-runtime/bin/rix-th06-run

# 自动确认菜单、移动、射击、放炸弹，120 秒后退出
/opt/rasterix/touhou/th06-runtime/bin/rix-th06-run --autoplay 120

# 独立结果目录，保存 GPU 帧及 LCD 采样，并记录硬件错误计数
python3 /opt/rasterix/touhou/th06_board_trial.py --attempt unique_name --seconds 90 --autoplay --hold 6
```

键盘方向键移动，Z 确认/射击，X 炸弹/返回，Shift 低速，Esc 菜单。应先正常退出其他 GPU 程序。自动操作只注入普通游戏输入，没有修改血量、碰撞或关卡脚本。LCD 触摸控制未映射到本游戏，音频与真实 USB 操作仍需单独验证。

## 证据位置

板上每轮保存于 `/opt/rasterix/touhou/results/<attempt>`：`result.json`、`samples.json`、`game.log`、`dependencies.log`、`frame.ppm`；启用 hold 后还保存 `lcd.bin`。主机通过串口整文件 SHA256 回读到 `report/touhou` 及 `report/postproc_th06_*`。最终结论以 `report/touhou/acceptance.json` 为准。

`stable01` 是修复默认纹理槽后的早期诊断：90.56 秒，退出 0，呈现采样 23.20 FPS，弹幕采样最大 96，纹理耗尽 0 次，所有硬件错误为 0；当时二维投影尚未修复。`pacing01` 验证了新时钟能消除大部分重复等待，但同样不是完整画面验收。后续完整画面与对照测试另记于验收报告。

最终使用同一个二进制、官方素材和输入 bot，依次运行 `legacy_final`（70 秒）与 `optimized_final`（90 秒，另留帧 6 秒）。比较两轮 20～65 秒内的真实关卡采样，排除启动、末帧回读与留帧时间：

| 指标 | 旧循环 | 优化循环 |
|---|---:|---:|
| 持续渲染 FPS | 23.73 | 29.94 |
| 逻辑更新 Hz | 47.47 | 59.98 |
| 游戏帧推进/秒 | 47.47 | 59.98 |
| GPU 每帧忙时中位数 | 6.418 ms | 6.448 ms |
| 比较区间弹幕采样最大值 | 88 | 79 |

渲染提升 **26.16%**；旧循环推进较慢，两轮同一墙钟时刻的场景负载可能不同，这不是固定回放逐帧渲染基准。GPU 忙时不是整个渲染/传输/显示时延。当前目标是约 30 FPS，未达到 60 渲染 FPS。

`quality01`、`legacy_final`、`optimized_final` 均退出 0、纹理分配错误 0、硬件错误 0，二进制 SHA256 均为 `63c2d3c693162914475a4545425bbeed1f333c8d37f5cd48be3d57204f953aae`。最终 LCD 的 6000 个采样像素与 GPU 前台帧最近邻放大完全匹配。BOOT.BIN 与 DTB 摘要保持原已验证值。板上安装通过逐块与整包 SHA256 校验，运行包 `894e3529916fae28f676501aa9843086259d5bab85923d0a367ac83a68035055`、素材包 `5eaadc614964eb9c0ad9ac9eeef0de7d3f629fe635a4eeacc4c8c3e43fad40af`。

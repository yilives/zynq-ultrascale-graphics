# Linux 已启动、RGB LCD 无画面：首帧参数修复

2026-10-16，用户确认修订启动包可以进入 Linux，连接的屏幕为 800×480 RGB LCD。COM11 实际登录确认内核为本项目的 Linux 5.4.0，根分区为 SD 的 `PARTUUID=52495831-02`。完整重启日志包含 `<debug_uart>`、U-Boot 2026.01 横幅及 Linux 登录提示。

## 板测定位

初始系统没有加载 RasterIX 模块，也没有启动游戏或 smoke。手动加载 `rix_dma_proxy.ko` 和 `plgpu_display.ko` 后，三个设备节点均出现；ABI 为 `0x52495801`、配置为 `0x9adb505e`，MIG/像素时钟就绪，所有错误计数为 0，显示使能和呈现帧数为 0。

运行 `rix-smoke 1` 时，初始 64 字节 DDR STORE/LOAD 比较完成，随后真实渲染器初始化。首帧收到 1753 个命令拍，产生一次 swap，但 copy/presented 均为 0，程序报告 `display ioctl errno=5`。状态为 15，解码首错为 1，即帧桥输入参数检查失败；DDR 读错、写错、超时及扫描错误仍为 0。

| 项目 | 原用户态编码 | 现有硬件约定 |
|---|---|---|
| 每片区可见像素 | 400×80=32,000，被编码为 32,768 | 片区连续存放 |
| 整帧换帧像素数 | 400×240=96,000，被编码为 96,256 | 帧桥严格要求 96,000 |
| 首帧结果 | 帧桥拒绝并锁存错误码 1 | 不提交错误帧 |

原因是 `FramebufferCmd::setFramebufferSizeInPixel()` 沿用了纹理页对齐。旧命令将 96,000 按 2048 对齐后得到 96,256，与本项目帧桥可见尺寸契约不一致。

## 源码与回归

`scripts/prepare_sources.py` 为主及游戏嵌套 RasterIX 同步加入 `RIX_FRAMEBUFFER_EXACT_SIZE` 分支；本板生成的 CMake 配置始终启用此分支。清屏/提交命令保持 32,000 像素，整帧 swap 保持 96,000 像素。硬件参数、地址和 DMA ABI 未变。

`sim/test_framebuffer_sizes.cpp` 使用真实 C++ 命令类，断言以上像素数并生成三条指令：`207d0012`、`207d0011`、`21770094`。扩展 GPU 仿真直接读取这些指令，在真实 IF 核验证 400×80 清屏、恰好 500 次 128 字节 DDR 写入和 96,000 像素换帧；最终 B 响应到达前禁止 swap。扩展多突发测试同时修正了测试存储模型在旧 B 待答时继续接受新 AW、导致丢失待答状态的问题。

C++ 断言、完整片区 GPU 仿真、非 OK B 阻断和 STORE/LOAD 回归均已通过。源码和仿真输入摘要绑定于 `report/framebuffer_contract.json`，新增为发布清单的第 25 项门禁。

## 后续板测状态（2026-10-18 更新）

首次故障后已完整重启并恢复状态 3。精确像素命令和临时 DMA 模块随后在板上使实际 GPU 出图；用户已确认 RGB LCD 可见游戏画面。游戏启动画面 60.45 秒呈现 1808 帧，约 29.91 FPS，采样错误计数为零；比赛和 30 分钟验收仍未完成。

复测还发现两项软件问题。旧 DMA `release` 即使空闲也调用 `dmaengine_terminate_sync`，底层 Linux 5.4 AXI DMA reset 同时影响两个方向，导致另一方向 IRQ 关闭；现仅在活动传输时 terminate，空闲时 synchronize，实际 smoke 和游戏退出后双向 IRQ 均保持开启。smoke 的旧读回未调用 `setRenderResolution`，读回仍按默认 640×480 定位；现显式设置 400×240，并修复 Renderer 初始后缓冲与 swap 后前/后缓冲地址选择。真实 Renderer 的旧缺陷负向复现和新逻辑回归均已保留。

用户随后报告界面比例与铺满问题，原因是旧 UI 画布过小而图案/菜单仍用固定像素尺寸。800×480 逻辑画布、400×240 视口和输入映射的后续修复见 [比例修复记录](LCD_LAYOUT_2026-10-18.md)。COM11 已恢复，新布局完成 1000 帧 smoke、60 秒启动图和实际 GPU 像素读回；两个程序及 DMA 模块已写入 SD 根分区，正常重启后摘要、模块和 smoke 再次通过。用户暂时无法观察修复后的 LCD，输入与比赛另待验收。

证据见 `report/physical_display_2026-10-16.json`、`report/board_serial/com11_smoke_1.log`、`report/board_serial/com11_after_reboot_ready.log`、`report/framebuffer_size_fixture.log` 和 `report/tb_gpu_exact.log`。完整发布和物理结果以最新清单及板测记录为准。

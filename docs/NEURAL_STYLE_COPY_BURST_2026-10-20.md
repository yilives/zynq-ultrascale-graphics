# FPGA 帧复制突发化与显示重叠

## 改动

数据顺序保持为：ARM 游戏逻辑 → RasterIX 400×240 → 独立完整帧快照 → A53 四核取帧并缩到 160×96 → FPGA 三层 INT8 CNN → 160×96 显示双缓冲 → FPGA 五倍双线性放大 → 800×480 LCD。风格化在放大之前。网络权重、量化运算和 414,738 周期的 CNN 核心没有改变。

上一轮 NNS2 已达到 23.7876 FPS，但 PS → PL 的复制桥仍逐笔读取 64 bit、展开 RGB565 后逐笔写入 128 bit。需要快照时还要额外写一次，固定地址和响应开销较大。

本轮 `rix_frame_bridge.v` 默认每次读取 16 beats，使用一块 BRAM 保存这批不可变源像素，再分别突发写入原始显示槽和快照槽。重复写入使用同一缓存，不重新读取可能被游戏复用的 PS 缓冲。读取 / 写入尾块根据剩余长度计算；地址、长度和 WLAST 在背压期间保持稳定，AW / W 独立握手。只有所有写响应返回且成功，才发布完整帧；错误、超时和取消仍需排空已接受事务。

选择 16 beats 与现有 PS HP 通路相容，源接口仍为 64 bit，目标接口仍为 128 bit，没有修改 PS 初始化或 DDR 布局。AMD 的 [HP 端口调优说明](https://xilinx-wiki.atlassian.net/wiki/spaces/A/pages/688128001/Traffic%2BShaping%2Bof%2BHP%2BPorts%2Bon%2BZynq%2BUltraScale)也将突发长度列为带宽因素；实际收益以下面的整机实测为准。

用户程序同时允许下一帧的取帧 / CNN 与上一帧等待显示切换重叠。队列最多保留一次未确认切换；复用旧显示槽之前，必须先读到 `accepted_prepare = prepare && scan_idle` 对应的确认，确保旧读取器已经排空。退出和诊断读回之前也等待最后一次确认。计数区分提交和硬件确认，最终处理帧数必须与两者相等。

## 已完成的本地验证

完整 400×240、原始显示和独立快照的协议仿真中，单 beat 对照为 1,260,022 周期，16 beats 为 171,005 周期，约 7.37 倍；读取事务由 24,000 降为 1,500，含快照的写事务由 48,000 降为 3,000。这是仿真复制阶段结果，不能当成游戏 FPS。

测试还包括尾块、4 KiB 边界、AW 晚于 W、随机背压、租约保持、源地址变化、中途取消、RRESP / BRESP 错误、提前 / 迟到 RLAST 和在途超时排空。已有显示 / 快照 / 五倍放大回归通过。独立复制桥综合为 285 LUT、398 FF、1 BRAM、0 DSP；整机导出还会检查缓存实际映射到 RAMB。

显示槽所有权测试在主机和 A53 上验证两种显示模式、两个初始槽、阻塞 / 重叠两模式，以及 3–250 ms 的确认延迟和超时；每种配置经过 1,600 次切换。旧硬件上的同程序短测为阻塞 23.7649 FPS、重叠 23.9363 FPS，等待主要移到了源快照，因此没有把软件重叠单独作为显著提速。

正式入口连续处理 1,764 帧、62.0325 秒，约提升 **19.54%**。本轮阻塞对照处理 1,767 帧、62.0180 秒，两次使用同一执行文件、同一模型，并确认运行前后文件哈希未变。每次提交数、硬件确认数和最终处理帧数完全相同，GPU 五项错误均为 0。卸载空闲驱动后，正式入口还验证了自动重新加载；ARM / FPGA 两后端均通过正常时限退出和 SIGTERM 退出。结束后 31 项安装文件匹配清单，无残留 GPU 客户端、快照租约或过期事件。

阻塞与重叠的差异约 0.2%，没有证据表明重叠单独提高吞吐。重叠将每帧约 7.46 ms 的显示等待转移到了源帧等待；新默认模式每帧源帧等待约 10.29 ms、四核读取 4.60 ms、准备输入 1.30 ms、含 PIO 推理 18.58 ms、写显示缓冲 0.31 ms。复制桥显著提速后，源帧供给和 PIO 仍限制整机帧率。各 FPS 来自独立自动操作会话，未声称输入逐帧相同；本轮仅重新测量 Neverball 的游戏性能。

两组真实输入由主机 NumPy 独立复算，每组 122,880 个张量值（其中 46,080 个有效 RGB 通道值）逐位一致；每组 61,440 字节原生显示缓冲及 6,000 个实际 LCD 采样也完全一致。网络权重、7×7 感受野和五倍双线性放大没有变化，`quality_acceptance` 仍为 `false`；本轮没有增加新的风格质量训练。

升级前后固定图案测试均已通过：独立 PS `glReadPixels` 与 PL 快照完整 96,000 个 RGB565 像素一致，方向为 top-down，租约保持时游戏继续渲染；两次运行的 smoke 二进制、PS 参考帧和 PL 源帧 SHA256 完全相同。COPYING → READY 的单次软件采样从 25.562 ms 缩短到 2.358 ms，约快 10.84 倍。采样间隔 200 µs，含软件调度误差，不代表精确硬件周期或延迟分布。原始证据及主机独立校验位于 `copy_static_before/`、`copy_static_after/`。

根分区只清理已在电脑持久保存、SHA256 完全相同的过时传输缓存，当前包和启动备份保留。留有压缩、归档和缓存清理回执。最终交付仍为配套启动文件与运行包，不生成整卡 `.img`。

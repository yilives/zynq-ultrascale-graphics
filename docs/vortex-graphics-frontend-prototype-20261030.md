# Vortex 图形前端原型：功能与资源实测

日期：2026-10-30。平台：AXU3EG / XCZU3EG。

后续进度见 [并发前端与 Linux 接口验证](F:/1FPGA/Xilinxprj/prj2/rasterix-linux/docs/Vortex_并发前端与Linux接口验证_20261030.md)：四 warp 并发、完整可移植浮点 RTL 回归、用户态接口及 AArch64 编译已完成。小功能集调度加速约 2.95×，合成大批约 3.94×；但最大一批仍约 5300 万周期，必须优化绝对吞吐后再评估 MC 接入。本篇保留首版功能和独立核资源实测，现用游戏尚未切换到 Vortex。

## 当前结论

**已经实现可在 Vortex 上执行的 RasterIX 几何设备程序，并完成 SimX 功能验证与两种执行通道配置的真实 Vivado 综合。** 双通道配置的计算核、缓存、内核启动管理和 AXI 访存包装合计 **24,447 LUT /25,768 FF /12 DSP /20 BRAM36 等效**。

后续已完成双通道核的独立布局布线，结果为 **24,139 LUT /25,592 FF /12 DSP /20 BRAM36等效**。100 MHz内部建立/保持时序通过，余量分别为 **4.259 ns /0.011 ns**；42,693条可布线网络全部完成，路由错误为零。外部AXI/DCR接口约束与整机时序尚未验证。

这为共享执行架构提供了实测依据，但目前尚未完成 Linux/游戏适配、整机集成或上板。当前游戏渲染链路没有切换到 Vortex，不能报告游戏加速比或新的 FPS。

## 实现方式

```mermaid
flowchart LR
    A[ARM 游戏逻辑与图形状态] --> B[顶点和状态数据]
    B --> C[PL Vortex SIMT 核执行几何程序]
    C --> D[RasterIX兼容描述符与命令]

```

图示为目标集成结构。本轮实际完成的是 C→D 的设备程序验证和 C 所需硬件的独立综合；尚未将其接入正在运行的游戏。

使用官方 Vortex 提交 [`50cb174546ec69a3869b42b8871e932e4440511f`](https://github.com/vortexgpgpu/vortex/tree/50cb174546ec69a3869b42b8871e932e4440511f)。编译工具使用其指定的官方 v3.0.1 预编译包，并固定下载仓库提交及每个分片 SHA-256。

几何程序复用已验证的 RasterIX/R32 几何算法源码，编译成普通 RISC-V 机器指令；原源码中的 HLS pragma 不参与本次硬件生成。FPGA 硬件来自 Vortex RTL，不是之前面积超限的 HLS 几何 IP。所有几何源文件仍符合原 R45 输入摘要。

首版只启动一个工作项，以满足原算法全局暂存区的单所有者约束。它验证完整调用链的可执行性，尚未实现多图元或多顶点并行。为此明确关闭了设备程序的多线程静态初始化保护和分歧转换；这些编译设置不能直接用于未来的并行版本。

## 功能验证结果

| 验证项 | 结果 |
|---|---|
| 独立 CPU 参考 | 81 个冻结二进制文件逐字节一致 |
| Vortex 四通道配置 | 45 组用例、54 次设备调用通过 |
| Vortex 双通道配置 | 同样的 45 组、54 次设备调用通过 |
| 输出记录 | 两配置各 213 条，包含三角形和状态命令 |
| 对比范围 | 每次完整 4 MiB 数据池逐字节一致，返回值与结果缓冲保护字通过 |
| 机器码一致性 | 两配置均为 69,744 B，SHA-256 完全相同 |

用例包括六个视锥裁剪方向、非单位位置/纹理矩阵、变化的 w、四边形、strip 跨批次状态、线点、用户裁剪面、平面着色、光照、双面模板、polygon offset 和双 TMU。短 strip 用例为17个顶点，不能将此轮覆盖范围表述为大型世界或长时间稳定性测试。

设备程序 SHA-256：

```
52a8cbd0193396b529cdef07867b1660070327bd5835eda9c2f0ed709f6971ba
```

保留原4 MiB池 ABI、80 B输入顶点、192 B RasterIX三角形描述符和三条带命令语义。浮点编译使用 `-ffp-contract=off`。ARM端测试运行器只提交数据与检查结果，不执行被测几何计算；CPU参考在准备向量时离线执行。

本轮沿用400×240、三条80行带的冻结协议，没有提高游戏分辨率。

这是 **SimX 设备指令执行验证**，不是 FPGA RTL 功能仿真或开发板实测。原始结果里的 `simulated_cycles` 是累计 MCYCLE；它包括多次调用过程，不能作为单调用延迟。模型存储时序也未拟合本板 DDR，因此本轮不据此计算 FPS 或加速比。

## 实际综合资源

目标 `xczu3eg-sfvc784-1-i`，顶层 `Vortex_axi`，Vivado 2026.1。Xilinx浮点IP采用全局综合，结果中没有未计面积的黑盒；锁存器数量也为零。

| 配置 | LUT | FF | DSP | BRAM36等效 |
|---|---:|---:|---:|---:|
| 1核、4warp×4线程、ALU/FPU/LSU各4执行通道 | 34,709 | 36,625 | 24 | 22 |
| 同样的线程配置，各2执行通道 | **24,447** | **25,768** | **12** | **20** |
| 双通道配置，独立布局布线后 | **24,139** | **25,592** | **12** | **20** |

两配置均保留16 KiB指令缓存、16 KiB数据缓存、KMU、128位AXI访存适配；共享内存关闭，Vortex自带TEX/RASTER/OM/RTU/TCU扩展关闭。其像素工作由现有RasterIX承担。

此次缩减的是运算和访存通道，不是通过删减几何功能降低面积。机器码相同也不等于两配置吞吐相同；当前只有一个工作项，尚不能用这些测试比较满载性能。

### 与底座组合的容量账

| 资源 | 既有无FSR底座 | 双通道原型 | 名义合计 | 器件剩余 |
|---|---:|---:|---:|---:|
| LUT | 38,050 | 24,447 | **62,497（88.57%）** | **8,063** |
| FF | 43,594 | 25,768 | 69,362 | 71,758 |
| DSP | 157 | 12 | 169 | 191 |
| BRAM36等效 | 71 | 20 | 91 | 125 |

这是两个报告的名义相加，不是整机布局布线结果。尚未计入新的 AXI-Lite 控制、缓存刷新/写事务排空、Linux设备接口及必要互连。若仍采用整片LUT预留10%的筛选目标，给这些新增逻辑只剩 **1,007 LUT**；若按器件绝对容量，则剩8,063 LUT。10%是工程余量假设，不是AMD强制要求。

若改用上述独立布线后的核面积做预算，名义合计为 **62,189 LUT（88.14%）**，绝对余量 **8,371 LUT**；90%筛选目标下余量为 **1,315 LUT**。两种口径均未计完整集成成本，不能把两个独立布线结果相加当作整机时序已闭合。

与此前“25K够不够”的区别在于：现在获得了一个24,447 LUT计算配置的真实综合结果和同程序功能验证；仍不能据此宣称包含所有集成设施的完整前端已部署。

## 文件与复现入口

源码：`src/vortex/geometry_frontend_r1/`。主构建目录：`build/minecraft-java-125/vortex-frontend-r1/`。

| 文件 | 内容 |
|---|---|
| `fixture-proof.json` | CPU参考一致性 |
| `simx-r5.json` | 四通道设备执行结果 |
| `simx-2lane-r1.json` | 双通道设备执行结果 |
| `ooc-r1/` | 四通道真实综合报告和DCP |
| `ooc-2lane-r1/` | 双通道真实综合报告和DCP |
| `route-2lane-r1/` | 双通道独立布线、内部时序报告和DCP |
| `audit-r1.json` | 源码、机器码、报告摘要及容量复核 |
| `upstream-line-endings.json` | Windows→Linux的纯换行转换记录 |

准备脚本为 `scripts/fetch_vortex_tools_r1.py`、`prepare_vortex_frontend_r1.py`、`prepare_vortex_2lane_r1.py`；构建入口为 `run_vortex_frontend_r1.py`，综合入口为 `synth_vortex_frontend_r1.tcl`。执行记录保留在各轮日志和build JSON中。重跑采用新的attempt编号，不覆盖旧结果。

Windows检出后，先运行 `scripts/normalize_vortex_checkout_r1.py` 处理纯换行差异，再进入WSL构建。双通道Vivado独立工程为 `F:/1FPGA/Xilinxprj/prj2/_vxg2/vx/vx.xpr`；它是前端原型，不是包含PS与RasterIX的整机工程。

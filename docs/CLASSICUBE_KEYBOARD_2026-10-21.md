# ClassiCube 键鼠操作与交互适配

本轮按用户选择，以 USB 键盘和鼠标作为操作方式。保留前一轮方块世界和四边形提交优化，并补齐实际 X11 / SDL 输入路径、LCD 菜单指针和窗口尺寸适配。实体键鼠尚未连接；自动验证范围和人工操作边界在下文列出。

## 启动与操作

将键盘、鼠标接到开发板 USB Host，可通过 USB Hub 接两件设备。在 PS 串口 COM11（115200，8N1，无流控）登录 Linux，启动：

```sh
rix-classicube
```

默认持续运行，直到从游戏菜单退出或收到 Ctrl+C / SIGTERM。`--seconds 0` 与默认相同；诊断时可设置 `--seconds 30` 等有限时长。

| 操作 | 键鼠 |
| --- | --- |
| 移动 | W / A / S / D |
| 跳跃 | 空格 |
| 转动视角 | 移动鼠标 |
| 挖掘 / 放置 | 左键 / 右键 |
| 拾取瞄准方块 | 鼠标中键 |
| 切换快捷栏 | 1–9 或滚轮 |
| 打开方块栏 | B |
| 暂停菜单 / 返回 | Esc |
| 选择菜单、方块 | 移动鼠标并左键点击 |
| 存档 | Esc → Save level → 输入短英文文件名 → Enter |
| 退出 | Esc → Quit game |

可在 Options 的鼠标设置中调整灵敏度，或从串口指定：

```sh
rix-classicube --mouse-sensitivity 30
rix-classicube --map /opt/rasterix/classicube/profile/maps/cc_gameplay_v4.cw
```

灵敏度范围 1–200；数值越大转向越快。默认不反转纵轴、不开平滑鼠标，已有配置会保留。显示固定为 800×480 LCD 全屏；F11 不改变内部渲染分辨率。

## 本轮修复

1. **正确的游戏客户区。** 原 X11 Matchbox 管理器为标题栏和面板预留空间，真实窗口曾被压为 400×174。现在仅对 ClassiCube 设置 SDL 的 X11 override-redirect 和无边框窗口，固定客户区 400×240。这样渲染纵横比、菜单和鼠标坐标使用同一个空间。
2. **菜单排版。** 界面按 0.5 的逻辑比例排版，适配两倍放大的 LCD。暂停菜单、选项、方块栏可使用 400×240 的有效区域；快捷栏同时调整为可读大小。
   超出单张纹理宽度的单行文字使用原引擎的省略号裁切，避免连同字高一起压缩而变形；较长文字不会在一行中完整显示。
3. **LCD 可见的鼠标指针。** X11 系统光标属于另一条显示层，不会自动混入 RasterIX 扫描出的游戏帧。本版在菜单 GUI 中由 RasterIX 绘制黑白指针，直接使用 SDL 接收的窗口坐标。进入游戏后恢复相对鼠标转向，隐藏菜单指针。
4. **鼠标捕获与失焦。** SDL 相对模式成功后不再每帧反复把指针拉回中心；相对模式失败时使用原引擎的光标差分回退。打开菜单释放相对模式，限制指针留在游戏客户区。窗口失焦期间忽略新的按下、系统重复按下和相对转向事件，释放事件仍正常处理；自动复测额外保持 W 半秒，检查它不会被重复事件重新置为按下。
5. **正常交互生命周期。** 默认取消测试时限，正常菜单关闭也生成退出记录并释放 GPU / 公共游戏锁。加载新地图使用独立的加载超时计时，避免游戏运行超过 45 秒后换地图被旧计时误判。

本轮未改 BOOT.BIN、DTB、FPGA bitstream、其他游戏私有 GL 或 CNN 模型。原 v4 审计目录迁到 SD 的 `rasterix-classicube-cache-archive-20261021/delivery-v4/`，原路径保留链接，逐文件 SHA256 校验后才释放根分区副本。

## 自动验证的边界

测试链路为 `XTEST → X11 → SDL2 → ClassiCube 原生输入处理器 → 实际世界变化`。它不使用前一轮直接调用 `Input_SetPressed` 的 autoplay，不直接设置玩家位置、视角或方块。原生扩展只记录状态、统计 SDL 事件和用户方块变化，并按请求冻结一帧供独立 LCD 回读。

测试检查窗口初始焦点、W/空格移动跳跃、相对转向、数字/滚轮快捷栏、中键拾取、左键挖掘、右键放置、Esc 菜单、选项、B 方块栏、点击选择方块、在 Save level 中输入文件名并实际保存、焦点切换清除按键、F11 固定尺寸、持续运行超过原 65 秒看门狗和点击 Quit 正常退出。

各界面同时回读 400×240 GPU 原图和输出端 6,000 个 LCD 采样点。菜单指针还按代码定义的黑白像素检查位置，不能用 X11 桌面的截图代替 LCD 输出。

键鼠版的完整输入测试持续约 71 秒，19 项主机输入/图像检查通过，包含失焦后的自动重复检查。暂停菜单、选项、方块栏、游戏视角、存档输入框五组共 30,000 个 LCD 采样点全部一致。通过菜单保存的 `.cw` 由主机独立解析 NBT，再与重载世界的全部 65,536 个方块校验值比较。

正常重启后，空 RAM 缓存重新加载当前程序与素材，通过键鼠菜单创建的地图也成功恢复；客户区仍为 400×240，焦点和相对鼠标模式正常。连同地形、存档重载和重启恢复，八组共 48,000 个 LCD 采样点零差异。最新 [整体验收清单](../report/classicube/keyboard-acceptance.json) 为 **29/29**，GPU / DMA / 扫描错误均为零，原 BOOT、DTB、私有 GL 和 CNN 安装文件校验值一致。

在完整 400×240 客户区、64×64×64 地图、32 格视距下，自动移动地形短测的 LCD 实际呈现约 **47.9 FPS**；平地交互约 60 FPS。该结果使用硬件 `presented` 计数，前两秒为预热；前一轮 400×174 客户区的性能数值只作历史记录，不与本版当作相同画面比较。

USB HID 枚举、硬件按键接触、鼠标真实 DPI 和手感仍需要连接实体键鼠后确认。自动验证不会把这些项目记为已通过。本轮不增加触摸摇杆。

板上已枚举到 USB 2.0 / 3.0 根集线器及 USB Hub；当前内核的 `CONFIG_USB_HID`、`CONFIG_HID_GENERIC`、`CONFIG_INPUT_EVDEV` 均为内建支持。当前 `/proc/bus/input/devices` 仍只有 Goodix 触摸屏，这与“实体键鼠暂未连接”的状态一致。

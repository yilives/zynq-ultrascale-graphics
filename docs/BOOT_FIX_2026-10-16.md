## 发现并修复的兼容缺陷

供 U-Boot 使用的旧 Linux 5.4 设备树带有 `u-boot,dm-pre-reloc`。固定提交 `c4abf697920c6b4a2f3e24da5721fb27fa2e4ce6` 的 U-Boot 2026.1 中，`drivers/core/ofnode.c` 的 `ofnode_pre_reloc()` 使用 `bootph-*` 判断早期绑定，不再接受这个旧属性。该版本 Zynq 串口驱动也没有 `DM_FLAG_PRE_RELOC`，因此原树不能保证在横幅输出前绑定 UART0 及其依赖。源码摘录见 `report/uboot_early_path_audit.log`；阶段标记规则见 [U-Boot 官方说明](https://docs.u-boot.org/en/stable/develop/driver-model/design.html#pre-relocation-support)。

`scripts/uboot_control_fdt.py` 从 Linux DTB 单独生成 U-Boot 控制树，将 17 个节点的旧阶段标记迁移为 `bootph-all`，并补齐 `/firmware` 祖先，共 18 个阶段标记节点。检查覆盖 `/amba/serial@ff000000`、祖先总线以及时钟/固件 phandle 依赖。生成器验证所有其他属性和节点保持一致，供 Linux 5.4 加载的 `system.dtb` 文件字节不变。

`scripts/build_uboot.sh` 使用这个独立控制树构建上游 `u-boot.elf` 目标，同时启用 UART0 早期调试及 `<debug_uart>` 提示；基址 `0xff000000`，参考时钟 100 MHz。打包检查仍比较 ELF 的实际装载字节、完整 u-boot.bin、尾部控制树和实际 BOOT.BIN 分区。

| 本地检查 | 结果 |
|---|---|
| 真实旧树作为控制树 | 被拒绝 |
| 分别移除 UART0、`/amba`、`/pss_ref_clk` 的阶段标记 | 均被拒绝 |
| 修订控制树、依赖闭包及编译后调试标记 | 通过 |
| Linux DTB 及其他板级属性保持 | 通过 |
| ELF / bin / 控制 DTB / BOOT.BIN 实际分区内容 | 通过 |
| 发布清单 | 24/24 本地检查通过 |

证据为 `report/uboot_control_dtb_build.json`、`report/uboot_early_console_regression.json`、`report/uboot_control_dtb.json` 和 `report/uboot_bootph_package_console.log`。这些结果验证已发现的控制树缺陷及修复内容，尚不能证明这是物理启动停顿的唯一原因。

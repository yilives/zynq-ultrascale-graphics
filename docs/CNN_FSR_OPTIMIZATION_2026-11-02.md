# CNN＋PL FSR 后续优化与实机结果

2026-11-02。在已验收的 CNN→400×240 同帧细节融合→PL FSR 链路上，采用像素等价的 ARM 融合优化，并验证已有重叠取帧机制。Neverputt 同一球洞短测从 **30.02 FPS 提升到 37.99 FPS，增加 26.57%**。CNN 和 FSR 均继续在 FPGA 上运行。

本次没有改变 CNN 网络、两套 v8 权重、FSR 算法或游戏画质。没有新增 RTL 或位流；上板复用已验收的 NGR1，退出后恢复原 v23 与原生清晰菜单。新入口放在 RAM，未写 SD，普通菜单开关未改。

## 同场景对照

Neverball 旧场景本身约 25 FPS，不适合用来判断更快后处理的吞吐上限。本次增加 Neverputt `map-putt/01_easy.sol` 固定球洞；先测关闭 CNN/FSR 的源呈现，得到 **60.09 FPS**。没有把更换游戏带来的差异算作优化收益。

同一次 Linux 启动、同一 NGR1、同一游戏进程，漫画按 **A/B/C/C/B/A** 顺序，每轮约 10 秒。A 是原联合运行时＋串行取帧，B 是新融合＋串行取帧，C 是新融合＋重叠取帧。三个路径都启用 PL CNN、同帧细节融合和 PL FSR。

| 路径 | 第一轮 FPS | 第二轮 FPS | 总帧数 / 总秒数 | 汇总 FPS |
|---|---:|---:|---:|---:|
| A：原融合，serial | 30.1087 | 29.9283 | 604 / 20.1209 | **30.0185** |
| B：等价融合优化，serial | 31.9327 | 31.8608 | 642 / 20.1275 | **31.8967** |
| C：等价融合优化，overlap | 38.0194 | 37.9689 | 765 / 20.1347 | **37.9941** |

融合优化独立带来约 **6.26%** 整链路吞吐提升；与重叠取帧组合后，相对 A 提升约 **26.57%**。油画另测 B 为 **31.8051 FPS**、C 为 **38.0279 FPS**。八轮合计 **2714 帧**，提交与呈现完成数相等。

以上是固定球洞、短时后处理呈现吞吐，不是 Minecraft 帧率，也不是所有关卡稳定帧率。LCD 的刷新率与新图像生成速度分别记录。

## 实际修改

第一项是简化 A53 NEON 的精确舍入。原融合使用分母 100 的有符号最近舍入；有效分子范围为 -12800…12700。利用

```text
floor((abs(n)+50)/100)
  = floor((((abs(n)+50)>>2))/25)
```

右式分子最大 3212，在此范围可用 2622 的定点倒数精确求除 25，再恢复符号。省去原有乘 100 后的校正步骤。它是受范围约束的精确实现，没有改变舍入规则。

第二项利用 160→400 固定比例的五相循环。横向每五个输出对应两个输入步进，直接生成相同的整数插值权重结果，减少重复索引、系数读取和乘法。边界夹取与分母 100 的二维插值保持原样。该实现专用于 160×96→400×240；其他分辨率不能直接套用。

两项候选均独立保留。A53 CPU-only 按 A/B/C/C/B/A 测试，频率全程为 1066666 kHz：

| 微基准 | 两次均值 | 相对原版耗时 |
|---|---:|---:|
| 原融合 | 5.67624 ms | 100% |
| 只简化精确除法 | 5.43098 ms | 95.68% |
| 再加五相插值 | **4.01827 ms** | **70.79%** |

最终采用 `rix-cfs-poly`，融合耗时减少 **29.21%**。游戏与 CPU-only 的绝对耗时存在缓存和并行访存差异，因此各自在本组内比较。

第三项是验证并采用已有 `--frame-pipeline overlap`，没有把它描述为本轮新实现。后台线程取得下一张拥有租约的 SNP1 快照，复制到自有 ARM 缓冲，前台继续处理当前源帧；两者通过独立缓冲、源帧号与完成等待交接。退出时排空快照操作，再释放资源。CNN 与 FSR 的硬件计算目前仍然串行。

## 阶段耗时与剩余瓶颈

漫画各组按总耗时/总帧数汇总：

| 每帧阶段 | 原版 serial | 优化 serial | 优化 overlap |
|---|---:|---:|---:|
| 前台等待下一份快照 | 5.863 ms | 5.287 ms | **0.066 ms** |
| 缩小输入 | 1.332 ms | 1.355 ms | 1.394 ms |
| PL CNN，含输入输出 PIO | 9.310 ms | 9.330 ms | 9.294 ms |
| ARM 400×240 细节融合 | 5.681 ms | **4.252 ms** | **4.245 ms** |
| ARM 写 scratch | 1.970 ms | 1.990 ms | 1.983 ms |
| PL FSR LOAD | 0.795 ms | 0.779 ms | 0.792 ms |
| PL FSR COMPUTE | 8.185 ms | 8.189 ms | 8.161 ms |

overlap 模式下后台快照总耗时约 6.91 ms/帧，其中复制约 6.04 ms。它没有消失，而是与前台工作重叠，不能再次加到前台总耗时上；并行访存也略增加了某些阶段耗时。这组数据支持主要收益来自减少前台等待，不能解释为 DMA 带宽提高。

当前关键路径仍有 CNN 约 9.29 ms、融合约 4.25 ms、写回约 1.98 ms、FSR 约 8.95 ms，以及准备和控制。只将 CNN（含 PIO）与 FSR COMPUTE 两项相加已约 17.46 ms，超过 60 FPS 的 16.67 ms 预算。继续小改插值，很难让这条串行链路达到 60 FPS。

下一轮更有价值的方向按优先级为：

1. **让本帧 FSR 与下一帧 CNN 重叠。** 两个独立硬件核具备研究价值，但需要将 FSR 调用拆成启动/完成状态机，核对 scratch、内部缓存、输出银行与 tag 的生命周期，并确保异常时仍排空 AXI。当前尚未实现，不能用各阶段简单取最大值承诺帧率。
2. **继续减少 CNN 的 PIO 往返。** 本组输入约 1.40 ms、输出约 3.26 ms，可研究只传实际使用通道的打包接口或批量读取。需要接口/硬件改动及整数回归，当前没有将其收益计入结果。
3. **按游戏分别处理源帧限制。** Neverball 优化入口另测 198 帧、24.4827 FPS，源场景约 24.57 FPS。后处理提速无法让该场景提供更多源帧；需要回到该游戏的逻辑/渲染测量。Minecraft、其他游戏和 miniDP 的结果不能由本次测试推导。

## 精度、画质及资源

- 两个候选在主机上通过直接插值 oracle 与四组实际图像黄金向量。A53 每次通过 **105507 项**检查，包含有效范围内所有有符号舍入值、边界和保护矩形。
- 两个候选共八组真实融合帧与原版逐字节一致；两套 CNN 权重及 CPU 整数向量不变。
- 四组静态真实 PL FSR 完整回读 SHA256 与原 v23 定点参考一致，合计 **1536000 像素**。
- 八轮实时末帧由实际源 RGB565、PL CNN 张量和日志在电脑独立重算，**983040 个 INT8 值**一致，**768000 个融合像素**的完整摘要一致。
- 八幅实际 FSR 输出共 **3072000 像素**的完整 DDR 回读摘要与未改的 v23 定点参考一致；实际 LCD 共 **48000 点**一致。没有取得物理屏幕的全像素照片。
- GPU 读写错误、超时、下溢、扫描错误、快照重试和过期均为零；游戏、后处理及加载恢复正常退出。

本轮加速保持原图像输出，不代表新的艺术效果改进。仍使用原 3→8→8→3、三层 3×3 INT8 网络与两套较强 v8 权重。FSR 仍为既有 PL FSR1 定点 EASU12＋RCAS5。整机资源继续沿用 NGR1 路由结果：**65058 LUT、71711 FF、189.5 BRAM、325 DSP**，没有因为本轮软件优化增加 FPGA 资源。

## 运行与复现

板上 RAM 内已安装新入口，默认 Neverputt、优化融合、overlap 与 PL FSR：

```sh
python3 /tmp/rix-cnn-group-r1/cfs_fast_play.py --style comic --seconds 30
python3 /tmp/rix-cnn-group-r1/cfs_fast_play.py --style oil --seconds 30
python3 /tmp/rix-cnn-group-r1/cfs_fast_play.py --game neverball --style comic --seconds 30

# 控制同一优化版的取帧调度，用于复测
python3 /tmp/rix-cnn-group-r1/cfs_fast_play.py --style comic --frame-pipeline serial --seconds 30
```

入口先核对文件索引与此前完整静态证明，正常停止菜单，加载 NGR1 并创建绑定 boot ID/整份位流哈希的凭据；结束后恢复原 v23 和清晰菜单。已用 Neverball 完成新入口的实机运行/回读/退出验证。普通 GUI 尚未接入这个 CNN 开关，新入口没有设为开机默认；RAM 内容断电后需要重新部署。

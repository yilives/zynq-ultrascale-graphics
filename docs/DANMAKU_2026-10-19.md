# RasterIX 2D 弹幕批量渲染实验

本实验复用当前 AXU3EG RasterIX IF 固件，通过新的 AArch64 程序验证东方式 2D 弹幕负载。它是渲染压力演示，尚未包含关卡脚本、发射与消除、碰撞判定、计分或实体触摸操控。

## 分工与链路

ARM 计算精灵位置、准备顶点和绘制命令；RasterIX 在 FPGA 中完成三角形光栅化、纹理采样、透明测试和混合。顶点变换仍由 RasterIX 的 ARM 工作线程完成。ARM 在初始化时生成精灵和字形纹理，不在运行时逐像素生成游戏帧。

实际链路为：ARM 批量顶点 → DMA → RasterIX IF 三片区渲染 → PS RGB565 帧缓冲 → 帧桥 → PL XRGB8888 双缓冲 → FPGA 最近邻 2× → LCD。渲染分辨率 400×240，LCD 输出 800×480。复用已有风格化模块，测试使用 style 0；CPU FSR 和 Arm ASR 未参与该链路。

左侧 192×224 逻辑游戏区以原比例显示，右侧显示弹幕数量、透明模式和累计呈现帧率。纹理采用 128×16 RGBA 弹幕图集及 128×64 字形图集；按背景、弹幕、玩家和 HUD 批量提交。深度测试、深度写入、灯光和雾关闭，现有 RTL 的硬件配置保持不变。

## 实测条件与结果

GPU 100 MHz、默认精灵 8×8 逻辑像素（LCD 上 16×16）、不旋转，三个数量与三种透明模式组成九组，每组预热 6 帧后测量至少 8 秒。每个逻辑矩形由两个三角形组成。弹幕在游戏区内移动并反弹，时间步固定为 1/60 秒，用于重复负载；这不表示实际呈现已达到 60 FPS。

| 弹幕数 | 透明裁剪 | 半透明 | 加法混合 |
|---:|---:|---:|---:|
| 256 | 约 30.06 FPS | 约 30.06 FPS | 约 30.06 FPS |
| 512 | 约 30.06 FPS | 约 30.06 FPS | 约 30.06 FPS |
| 1,024 | 约 30.06 FPS | 约 30.06 FPS | 约 30.06 FPS |

最终原始结果见 `report/danmaku/final.json`。`arm_scene_ms_per_frame` 是移动与精灵顶点生成；`arm_frontend_ms_per_frame` 包括 HUD、GL 提交和换帧调用；`worker_dma_drain_ms_per_frame` 包括 ARM 顶点线程和 DMA 排空；`present_wait_ms_per_frame` 是排空后等待实际呈现的时间；`gpu_busy_ms_per_frame` 根据 PL 的 100 MHz busy 计数换算，可能与上述阶段重叠，不能相加当作整帧耗时。

旧 `PLGPU_WAIT_PRESENT` 使用 `msleep_interruptible(2)`，板上 HZ=250，会受到系统节拍取整影响。保留旧等待基线 `baseline.json` 后，新增程序默认以 300 微秒高精度休眠读取同一硬件呈现确认。没有跳过最后 AXI B 响应、垂直消隐换页或帧号检查。1,024 颗半透明弹幕从约 20.74 FPS 提升到约 30.06 FPS；内核驱动未改动。`--present-wait ioctl` 可复测旧等待方式。

**当前没有达到 60 FPS。** 此实验说明当前配置可以承载千颗小精灵的约 30 FPS 输出；更大纹理面积、旋转和重叠会增加负担，不能把数量直接作为所有弹幕素材的性能保证。下一步应测量完整帧桥和呈现时序，决定是否优化搬运和流水线。

扩展负载：1,024 个 16×16 逻辑像素精灵加旋转，半透明模式实测 20.04 FPS；4,096 个 8×8 逻辑像素精灵实测 15.03 FPS，均正常退出且硬件错误为零。结果单独记录在 `report/danmaku/rotated.json` 和 `4096.json`，不混入默认九组成绩。

## 显示与退出核验

每次初始化先绘制校验画面，回读 8 个位置，验证普通透明裁剪、半透明、加法混合、透明边角和全帧边界。最终九组完成后，通过 `--hold-last-seconds 90` 保持同一 GPU 前帧：实际 LCD 每 8 像素采样一次，共 6,000 点，与该帧最近邻 2× 的参考值全部匹配。见 `report/danmaku/lcd-check.json`、`final-frame.png` 和 `final-lcd-sample.png`。

RasterIX 的正常上下文销毁会提交换回 `COLOR_BUFFER_LOC_0` 的命令。退出后的默认画面可能是之前的四色测试图，不能用它代替演示画面核验。初版新增程序遗漏了销毁提交后的线程/DMA 等待和恢复帧的实际呈现等待，已补齐：最终程序先排空工作，销毁上下文提交恢复命令，再排空并等待恢复帧的硬件确认，最后释放回调对象和 DMA 缓冲。三个独立进程连续启停通过。历史采样与旧二进制分别保留为 `lcd-check-after-exit.json` 和 `build/danmaku/pre-shutdown-fix`，最终证据见 `report/danmaku/board-proof.json` 与 `acceptance.json`。

## 构建、打包与运行

使用已经配置的 SDK 与 `build/tuxracer-aarch64`：

```bash
bash scripts/build_danmaku.sh
python3 scripts/package_danmaku.py
```

构建运行宿主精灵几何检查并验证 AArch64 ELF，输出 `build/danmaku/rix-danmaku`；发布包为 `build/danmaku/rasterix-danmaku.tar.gz`，包含源码、独立启动入口、板测脚本及许可证。Windows 串口部署入口：

```powershell
.\scripts\deploy_danmaku_serial.ps1
.\scripts\install_danmaku_serial.ps1
```

板上程序保存于 `/opt/rasterix/danmaku`，现有游戏、BOOT.BIN、设备树与自启动选择保持原样。手动运行 10 分钟的 512 精灵演示：

```sh
/opt/rasterix/danmaku/rix-danmaku-run
```

运行完整矩阵，或者测试放大旋转负载：

```sh
/opt/rasterix/danmaku/rix-danmaku-run --seconds 8 --output /tmp/danmaku.json
/opt/rasterix/danmaku/rix-danmaku-run --count 1024 --mode alpha --sprite-size 16 --rotate --seconds 8 --output /tmp/rotated.json
```

入口会加载已有的匹配内核 GPU/DMA 模块并选择 FPGA 最近邻输出，拒绝已知其他游戏/超分进程并行使用 GPU；DMA 驱动也执行设备所有权约束。SIGINT/SIGTERM 会正常退出并完成上下文清理。

在 Windows 上验证已回收结果：

```powershell
python scripts/verify_danmaku_lcd.py
python scripts/record_danmaku_acceptance.py
```

SD 上的结果保存于 `/opt/rasterix/danmaku/results-20261019`。部署仅添加用户态文件，没有重新生成或写入 FPGA 启动包，也没有重建整卡镜像。实体 LCD 人眼观察和触摸操作未由本实验验收。

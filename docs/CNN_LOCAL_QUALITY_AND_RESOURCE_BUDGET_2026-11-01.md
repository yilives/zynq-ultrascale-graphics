## 实际硬件预算

芯片：XCZU3EG，70,560 LUT、141,120 FF、216 BRAM Tile、360 DSP。以下来自已路由的完整工程，各配置的资源余额不能相加。r1 是经过临时上板验证、尚未设为默认的独立候选，数据见其整机与实机验收记录。

| 配置 | LUT | FF | BRAM Tile | DSP |
|---|---:|---:|---:|---:|
| 默认 v23：单 TMU＋真实 CNN＋FSR | 64,901 / 70,560 | 71,349 / 141,120 | **216 / 216** | 325 / 360 |
| 已审计 Java 配置：双 TMU＋FSR，无 CNN | 65,624 / 70,560 | 74,028 / 141,120 | 149 / 216 | 330 / 360 |
| r1 候选：单 TMU＋原地 CNN＋FSR | 64,730 / 70,560 | 71,445 / 141,120 | **189.5 / 216** | 325 / 360 |

原默认 v23 的 LUT 账面余量为 5,659，但 8,820 个 CLB 位置均已有占用；不能把这些 LUT 视为能任意加入新模块的空间。该配置路由后 WNS 为 +0.306 ns。其首要容量限制为 BRAM 已满。新 r1 已回收 26.5 Tile，但 LUT 使用率仍为 91.74%、DSP 为 90.28%，不能只凭空闲 BRAM 宣称能加入任意网络。

默认配置的主要模块如下。层级统计存在共享/合并，LUT 子项不应作为完全独立可拆卸模块简单相加。

| 模块 | LUT | BRAM Tile | DSP |
|---|---:|---:|---:|
| FPGA FSR | 20,291 | 78 | 173 |
| RasterIX＋显示 | 12,938 | 54.5 | 84 |
| CNN | 4,466 | **55** | **65** |
| AXI 互联 | 17,570 | 0 | 0 |
| MIG | 7,640 | 25.5 | 3 |
| DMA | 1,545 | 3 | 0 |

默认 v23 原始位流 SHA-256：`035c30597ce7ed94dff24a733dbbb81fa68998e8d3fba52ef45902d23ccb01d9`。本轮重新核对原始位流、资源/时序报告、两套配置的路由检查点和层级报告哈希；来源与逐文件身份见资源 JSON 及 [架构审计](../report/architecture-audit-2026-10-28/resources.json)。这不是重新综合或重新测量当前开发板。

Java 配置虽然剩 67 BRAM Tile，但只剩 30 DSP，不能直接再加入原本占 65 DSP 的 CNN；需要单独降低并行度或调整架构，再做整机验收。

## 为什么参数少也可能放不下

真实 CNN 为三层 3×3、3→8→8→3、INT8，1,027 参数、7×7 感受野，物理计算阵列为 64 路 MAC。原双整帧核在 160×96 下约 414,738 周期、约 4.15 ms；新原地 r1 为 462,816 周期、名义 4.62816 ms。**均仅为 100 MHz 下计算核心时间，不含上传、融合、FSR 和呈现，不能据此宣称整条链路帧率**。

原双帧设计的主要存储是中间特征，而非千余个权重：两个 160×96×8 INT8 特征库共 245,760 字节。若直接改成 16 通道并保留两个全帧特征库，仅这些特征就需要 491,520 字节，按每 BRAM36 的理想 4,608 字节容量计算也至少要 107 块；还未计端口宽度、深度取整和权重/控制开销。原 v23 的整个 CNN 为 55 块且无空闲 BRAM，因此不能直接加宽。r1 通过单帧库改变了这项存储预算，未采用 16 通道网络。

本轮 PC 多尺度网络虽然只有 54,603 参数，却有归一化、下/上采样、残差连接等现有硬件不支持的算子。400×240 时仅卷积已约 5.115 亿 MAC/帧，60 FPS 对应约 307 亿卷积 MAC/s，未计其他算子与数据搬运。现有 64 路、约 100 MHz 核心的峰值约 64 亿 MAC/s，也不能将该模型视为可直接映射的网络。此模型只是画质/泛化探针，没有 FPGA 适配或容量验收。

## 本地验证结果

完整油画教师与动漫教师分别约 168 万和 214 万参数。本轮先重跑教师，再比较旧 INT8 网络与同一套 QAT 权重的浮点执行，最后测试 PC 多尺度模型。旧整数执行与历史缓存逐像素一致；完整教师重跑与缓存最大仅差 1 个 RGB8 灰阶。

旧 QAT 权重浮点执行与 INT8 输出平均差约为动漫 1.63、油画 4.05 个 RGB8 灰阶。两者对教师的误差没有显示浮点执行明显更好，说明问题不能只归因于 INT8。**这不是独立优化后的 FP32 模型对 INT8 的公平上限比较。**

新候选用 17 幅训练图，先训练 600 步低分辨率，再做 60 步全分辨率微调；没有新的独立世界验收。以下表格只比较同为 160×96 的结果，指标为世界区域 RGB8 MAE，越低表示越接近教师，**不等于更美观**。

| 风格 / 场景组 | 旧 INT8 | 新 PC 多尺度 | 变化 |
|---|---:|---:|---|
| 动漫 / 同世界验证 9 帧 | 7.162 | 8.133 | 误差增加 13.5% |
| 油画 / 同世界验证 9 帧 | 35.906 | 27.321 | 误差减少 23.9% |
| 动漫 / 历史另一世界路线 8 帧 | 10.529 | 16.774 | 误差增加 59.3% |
| 油画 / 历史另一世界路线 8 帧 | 37.683 | 61.745 | 误差增加 63.9% |

这 8 帧来自同一路线，并非 8 个独立世界。历史 `test_*` 标签在多轮研发中已经被查看，应当视为开发数据，不能声称新的盲测通过。新模型对部分训练场景拟合更好，跨世界明显变差；同时教师本身的画风也未被用户接受。因此没有选用新权重。

## 后续路线收敛

1. **先更换风格目标，停止继续蒸馏已否决的两种教师。** 推荐先寻找保留游戏内容、纹理辨识和轮廓的自然插画目标；这只是建议，尚未确定最终画风。需要先用若干原始场景确认教师效果，再扩展训练场景和做新世界留出验证。
2. **保留现有 FSR 的首轮候选，以新增 BRAM=0、新增 DSP=0 为设计目标。** 优先研究同宽度扩大感受野/上下文，而非直接加宽。例如三层膨胀率 1/2/3 可把理论感受野从 7 扩到 13，MAC 数不变；但寻址、边界、权重训练和兼容标识均须处理，尚未实现或验证画质，更没有整机可装入结论。
3. **分时复用更多层只节省计算资源，不节省时间。** 六层同宽核心理论计算约 8.29 ms，额外参数与控制也要修改；此前六层试验未通过画质选择。不能用层数增加代替有效改进。
4. **若同一资源包络达不到画质要求，就需要改存储架构或分配方式。** 分块/行缓存、DDR 特征回写、降低并行度，或独立 CNN 实验配置回收部分 FSR 资源，都是不同工程方案；均须重新估算带宽、延迟和整机路由。尚未采用，不移除现有 FSR 代码或生产配置。

换模型权重与更改网络拓扑/算子并不是同一种更新。新拓扑必须有独立能力标识和工具链验证，不能把不兼容的权重包交给旧位流执行。画质、INT8 一致性、整机路由、真实呈现时间都通过以后，才进入菜单和游戏路径。

## 重现与状态

本地环境：`build/neural-style/venv/Scripts/python.exe`，PyTorch 2.6.0 CPU、2 线程、关闭 MKLDNN。训练与推理均在 PC，不是 ARM 或 FPGA 速度测试。

```powershell
build/neural-style/venv/Scripts/python.exe -B -u scripts/local_style_lab.py prepare
build/neural-style/venv/Scripts/python.exe -B -u scripts/local_style_lab.py train --styles oil
build/neural-style/venv/Scripts/python.exe -B -u scripts/local_style_lab.py train --styles anime
build/neural-style/venv/Scripts/python.exe -B -u scripts/local_style_lab.py report
python scripts/local_style_resource_budget.py
```

以上是已执行实验的重现说明，**当前不建议再次训练这两个已被否决的目标**。数值结果保留用于解释选择；对照页已注明用户反馈和硬件限制。

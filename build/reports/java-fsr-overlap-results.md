# Java CNN 与 FSR 调度复测

在同一个已加载的 Minecraft Java 1.2.5 存档中，用相同的 NEON 漫画模型、400×240 源分辨率和 PL FSR 做了四段约 8 秒的交错测试。串行调度在 FSR 完成后继续工作，重叠调度在下一帧 ARM CNN 推理期间完成上一帧 FSR。

| 顺序 | 调度 | 完成帧 | 后处理帧/秒 | 源呈现帧/秒 |
|---:|---|---:|---:|---:|
| 1 | 串行 | 119 | 14.71 | 14.91 |
| 2 | 重叠 | 132 | 16.29 | 16.62 |
| 3 | 重叠 | 128 | 15.85 | 16.00 |
| 4 | 串行 | 137 | 16.90 | 17.08 |
| 加权 | 串行 | 256 | 15.81 | 16.00 |
| 加权 | 重叠 | 260 | 16.07 | 16.31 |

加权后处理吞吐差约 1.67%，两组区间重叠。FSR 前台等待从平均 8.46 ms/帧降到 0.002 ms/帧，说明调度成功隐藏了 FSR 等待，但渲染端供帧速度限制了输出。保留串行配置作为默认，重叠方式留作经过实机验证的候选。

四段均核对了最终整帧显示回读及各 6000 个 LCD 样点。测试先做 PL FSR 384000 像素参考比对，结束后正常关闭游戏、恢复 FPGA 配置和 15 项游戏库。第一轮交错测试被旧测试驱动的自动退出定时器截断，随后用独立测试类延长窗口，四段复验完整通过。

## Java 渲染异步提交

使用相同 Java 图形库的 async 策略。退出时仍通过原有 GPU 队列排空和 FPGA 配置恢复检查。先完成一次 12 秒短测，后处理 16.77 帧/秒。之后在单次运行内完成四段调度交错对照。

| 渲染提交 | FSR 调度 | 加权源帧/秒 | 加权后处理帧/秒 |
|---|---|---:|---:|
| 原 pipeline | 串行 | 16.00 | 15.81 |
| 原 pipeline | 重叠 | 16.31 | 16.07 |
| async | 串行 | 19.32 | 18.96 |
| async | 重叠 | 19.02 | 18.61 |

async＋串行的两个窗口为 17.92 和 20.01 帧/秒。同为串行 FSR，跨启动加权观测提升约 20%。结果来自静止存档短测。两次启动的 Java 调度和实际场景负载可波动，长时间移动与复杂地形帧率仍待验证。四段共 24000 个 LCD 样点零差异，退出码为零，开发板恢复到 15 项游戏库。异步路径目前通过独立联测脚本运行。

## Java 双 TMU＋折叠 CNN＋FSR

独立 Vivado 工程完成块设计验证。CNN 子模块综合使用 4561 LUT、17 DSP 和 28.5 BRAM Tile。GPU、DDR4、FSR 也已通过子模块综合。整板日志记录顶层与实现进度。

另行生成的 JC16 寄存器接口报告 1706976 周期。AXI 仿真覆盖普通输出、分组读取、回压和无效访问，6 帧共 210 像素与参考一致。整板资源试验仍使用早期接口，整板结果和 JC16 接口验收分别保留。Java 主线 GL 库当前按原配置验证能力寄存器，实机加载折叠版本还需要匹配新接口的加载凭据和运行时。
